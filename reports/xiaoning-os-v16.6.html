证据分级（每条评分必须能落到 E0~E3）

E0 · 文档声明
  • 有设计文档 / 手册 / 模块头
  • 只能证明「写了」，不能证明「生效」
E1 · 脚本存在
  • 有确定性脚本 / hook / 契约 schema
  • 能证明「可执行」，未证明「每次执行」
E2 · 门禁 + 留痕
  • 失败会阻断，且落 JSONL / tasks.log 证据
  • 能证明「本次生效」
E3 · 连续版本 + 失败回滚
  • 跨多版本 / 多项目重复通过，且有回滚与复盘
  • 才计入「成熟」
计分规则

每维 0~100：90+=有机制、有门禁、有连续证据；80~89=机制在但证据/覆盖不足；70~79=明显短板但有补强路径；<70=缺位。加权后四舍五入到 0.1。任何「文档写了」但无 E1 以上证据的能力，最高只给 88，避免把「设计完备」误当「运行成熟」。

03

人格体系 v2.4.16 深评

三模块 · 六层 · 25 模块 + 4 非人格面 · 双装载

人格体系仍是本体系最难被外部复制的部分：它不是「一段 system prompt」，而是 画像（叙事本体）＋ self-model（规范本体）＋ 人格矩阵（中间契约） 三模块，经 静态符号矩阵 → 编译面 → 装载面 确定性装配，再由 神经符号交叠 运行：符号侧算状态，LLM 只负责语言成形。

3.1 结构：六层 × 25 模块 × 4 非人格面

L0锚定规则层零周期 / 仅人签 / WORM安全伦理、身份锚定、系统硬约束（第 6/7 闸）L3

机制一：单字节真源（W2）

人格「装没装、是不是这一版」不看文档，只看 注入清单 的 内容 / 内容哈希 / 字节数。项目 bundle 只是缓存，不一致即 人格装载状态机自动校准。这把「在场 ≠ 采用」变成了可校验断言。

该不该做（人格三层裁决：规则层 → 人格层 → 宪法兜底 6 条）× 能不能做（AgentOS 三层：L1 静态 → L2 权衡 → L3 OS 兜底，unverified 不默认放行）。任一否决即终止，避免「能做但不应做」或「该做但越权」。

与 2026 研究界的对照

2026 年出现了专门测「长会话人格漂移」的基准（ContextEcho：25 探针身份套件，覆盖 3,746~9,716 轮、23 个前沿模型）与「长程人格坍塌」研究（Best Friends, Not Forever）。研究结论是：漂移普遍存在，且记忆架构不能单独解决连续性。本体系的「符号状态 + 确定性装载 + 双裁决」正好是研究建议的方向，但尚未用这些基准自证——这是人格维从 94 走向 96+ 的唯一硬缺口。

八维逐维评分与证据

v15.5 → v16.6 增量

① 架构（96 → 97）｜权重 15%

为什么加 1 分：v16 把「状态机范式」上升为 OS 四层，模块从「隐性经验」变成 18 个有编号、有契约、有边界卡的单元；OS 层十服务（身份/通知/裁决/受控执行/SOP/门禁/记忆/检索/路由/更新）把原来散落在 规则与脚本里的能力集中为「唯一装载入口」。这是结构性进步，不是换皮。

证据（E2~E3）
  • 18 模块头 + 9/9 层本体卡 + 映射表（DE 51 / 孤儿 0 / 豁免 0）
  • 单字节真源 + 人格装载状态机 自动校准 + 人格校验
  • 任务状态机 九态、签署闸门、交接确认、受控执行契约
为什么不给 98
  • v16.0.0 于 2026-11-02 发布，v16.6.0 于 11-07，架构只跑了 6 天
  • 守护层/双框协作 仍 预留；守护层与双框没有连续运行证据
  • 「模块数」口径存在多义（19 份模块头 / 30 份含子目录 / 21 份文档计数）

② 治理（98 → 98）｜权重 15%

为什么持平：治理仍是全体系最强维，v16 新增 受控执行框架五段、收尾自举四类检查、发布门禁，并把规则冻结（16 条，一进一出，2026-11-02→12-31）做成机器可判。这些是「把治理做深」，但边际提升已很小；同时暴露出「需要冻结」本身就是规则膨胀的反证，因此不给 99。

治理机制落地物证据等级与业界对照
人工签署只读闸签署闸门（PreToolUse 拦截待签 spec）E3强于 Devin standing permission（后者是分层授权，无 WORM 证据链）
WORM 三副本 2/3防篡改三副本校验 + 哈希链E3业界少见；多数产品只做审计日志，不做防篡改
三角色分离55 执行 / 19 校验 / 2 终审 / 1 双模；执行∩校验=∅E2对应业界「maker-checker」，但本体系把它做成 agent 目录约束

受控执行框架契约 → 幂等 → 四证 → 失败分类 → 自更新E2与 ABC（Agent Behavioral Contracts）同向，但本体系已运行

③ 记忆（90 → 91）｜权重 12%

加 1 分：ContextPack + 标签层 + 双写（tdai + mcp_Memory）+ qdrant 三 collection 分权（fullstack 自动入库 / system_kb 须人签后 migrate）+ 写入门控（置信度 ≥0.7、来源可溯、冲突检测）形成了「谁记忆了什么 / 谁有权读 / 能否审计」的完整语义。

为什么不能更高：外部记忆工程已经把「召回」量化到小数点——Mem0 在 LoCoMo 92.5、LongMemEval 94.4、BEAM-1M 64.1（Letta LoCoMo 74.0）；本体系没有任何一项可比的公开回测。四套分工是「语义切割」的优势，但没有数字支撑，就只能停在 91。

④ 自主防漂移（93 → 95）｜权重 15%

加 2 分：v16 的 前置裁决契约 把「查不了」明确为 unverified ≠ allow，这是防漂移的关键一次语义收紧；配合唯一写者、append-only、human-override、运行时校验 五断言（提交复核 / 停滞 / 元评审 / 缺陷双产出 / 冲突裁决），以及危险命令 L3 硬断（100 条 dry-run 误拦 0 / 漏拦 0），形成「事前裁决 + 事中停滞 + 事后四证」的闭环。

研究侧印证（2026-02 ~ 2026-10）

ABC（arXiv 2602.22302）在 200 个场景、7 个模型、6 家厂商上做了运行态契约强制，结论是「所有模型都会漂移，契约能把漂移显性化并约束」；ContextEcho（arXiv 2605.24279）用 25 探针在 23 个前沿模型上测长会话人格漂移。这说明本体系的方向不是「过度设计」，而是提前一年做了研究界正在追认的事。缺口同样明确：没有接入这些基准自证。

⑤ 人格（91 → 94）｜权重 12%

加 3 分：v2.4.16 把人格从「六层结构」推进到「25 模块 + 4 非人格面 + 35 锚 + 双档 bundle + 单字节真源 + 锚点命中率」。四非人格面（能力面路由 / 三层裁决 / 工作能力面 / AgentOS 执行裁决面）与 L0-L5 正交、只读消费，避免「把工程决策塞进人格心理层」的常见污染。详见 §03。

⑥ 工程化（88 → 92）｜权重 10%

加 4 分（本版最大增量）：① 评测基线 v1（70 例：gate 20 / adjudication 20 / persona 30）+ baseline + 评测执行器 --compare + 发布门禁评测剖面 五维剖面；② 受控执行框架与检查器；③ 发布门禁 14→16 项；④ 收尾自举四类检查（说明书覆盖 / 文档版本 / SOP 版本链 / 自身项目对接）；⑤ 接入标准 接入验收项，两项目全项通过。

扣分项：仍无 CI / 无第三方基准 / 无外部代码审计；文档计数与快照存在可验证的漂移（§13）。

⑦ 生态（76 → 77）｜权重 8%

加 1 分：MCP 作为「外设子类」被消费而非绑死，项目接入标准可移植（软链安装 + project@1 + os-align），模型不绑定。外部生态在 2026 年进一步标准化：MCP 月 SDK 下载 9,700 万、注册 server 1 万+，2025-12-09 Linux Foundation 成立 Agentic AI Foundation（MCP / goose / AGENTS.md），2026-07-28 版规范（RC）走向 stateless core + Extensions + Tasks + MCP Apps，A2A 与 MCP 同治理体、互补分层。

为什么仍只有 77：本体系是单实例深度，没有公开 SDK / registry / 第三方复用；生态广度不可比，这是结构性短板，不是靠再写几个模块能补的。

⑧ 实证（94 → 95）｜权重 13%

加 1 分：两个常驻项目均完成全量接入，并在 v16.6.0 发布当日完成对齐；项目 A 的全部验收项通过（含收束与质量复核），项目 B 的基础项、项目项、接洽点、模块落点、维度与收尾六组全部通过（gap=0），且已有 400+ 轮的长期运行沉淀。

为什么不给 97+：v16 四层架构只运行 6 天；项目 A 自报「进化效果待回验」、批量外发未做；长线「误拦率 / 缺路径 / 漂移事件」统计仍缺。

  • v16.0.0（11-02）→ v16.6.0（11-07），6 个 minor / 5 天
  • 收尾自举本身就是「补漏机制」，说明收尾漏更是系统性问题

结论与 v17 演进建议

93.4 / A

14.1 总评

v16.6 完成了一次「从范式到平台」的抬升：OS 四层、18 模块、十服务、单字节真源、前置裁决契约、受控执行、评测 v1、双项目 全量接入。纵向看是 v15.0（90.8）→ v15.5（91.9）→ v16.6（93.4）。与 v15.5 相比，体系不再只是「一套很强的规则 + 人格」，而是一个有装载、有服务、有门禁、有映射面的运行平台。在「治理内建 + 人格机械化装载 + 运行态自守护」这三条主轴上，2026 年主流框架/产品/研究仍没有同构的公开先例。

但必须同时承认：v16 只运行了 6 天，生态仍窄，外部可验证性仍弱，用户态守护层与双框仍 预留。93.4 是「结构 + 证据」的分数，不是「长期可靠」的分数；后者需要至少一个季度的连续运行与一次真实故障复盘来换。

14.2 演进建议（按优先级 / 可验收）

优先级动作为什么现在做验收锚
P0接 1 个人格漂移基准 + 1 个记忆基准（ContextEcho 抽测 / LoCoMo + BEAM 子集）把「人格/记忆」从自说自话变成可比较数字；这是 94→96+ 的唯一硬缺口v16.7 发布说明出现首份外部基准成绩与失败样本
P0把本次 3 处漂移写成回归用例，并入发布前自动对账（接入档 / skills 计数 / 模块头口径）「收尾自举」已证明能查，但还没证明能覆盖这类语义漂移收尾自举检查新增 3 条断言，发布门禁 可复现拦截

P330 天长线基线：版本 × 项目回归矩阵，记录误拦率/缺路径/漂移事件把「实证 95」变成「实证 97」的唯一路径首份 30 天运行报告（含 1 次故障复盘）
一句话总结

这套体系已经越过「个人提示词工程」的阶段，进入「单人可维护的 Agent OS」区间；它现在最需要的不是再证明自己有多复杂，而是用外部可复现的测量证明自己有多可靠。前者已经足够，后者才刚刚开始。
