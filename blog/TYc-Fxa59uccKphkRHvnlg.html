第 01 篇 · 推理-行动交错范式：CoT 到 ReAct 的谱系


02SECTION

导读


Agent 范式的地基是 ReAct——「思考-行动-观察」交错循环。但要理解它，得先看它从哪来：CoT 教会模型「分步想」，ReAct 让模型「边想边做」，Self-Ask/ToT 补上「追问与分支」。本篇讲这条「推理-行动交错」谱系的每个节点、它们解决什么、留下什么局限（为下一篇 Plan-and-Execute 埋伏笔）。

04WHY

二、ReAct：为什么它是范式原点


2.1 机制

code

Thought（想：下一步做什么/需要什么信息）

  → Action（做：调用工具/API/查百科）

  → Observation（看：工具返回了什么）

  → 回到 Thought ……直到任务完成

•关键：推理被观察「接地」——不是凭空想，而是基于工具返回的事实继续想（减少幻觉、抑制错误传播）；

•与 CoT 的区别：CoT 的推理是「封闭世界」的（凭记忆），ReAct 的推理是「开放世界」的（查证后再推理）。

2.2 为什么赢

1可解释：每一步的 Thought/Action/Observation 都可回放——出错了能定位（对齐「审计留痕」思想）；

2可纠错：Observation 反馈天然驱动下一步修正（不用额外机制）；

3工程极简：本质是「一个循环」，任何框架都能实现——它是所有后续范式的最小公分母。

💡 学习要点：ReAct =「把思考接到地面上」CoT 让模型「想」，ReAct 让模型「想 + 查 + 再想」。范式跃迁不是「更聪明」，而是「与环境的闭环」——思考有了事实反馈，幻觉被抑制、错误可修正。

06SECTION

四、工程实践要点（何时用 ReAct）


1适合：需要查证的任务（问答/检索/调用 API）、短到中等任务链、交互式场景；

2不适合：超长稳定流程（重规划）、必须可审计控制的流水线（该用工作流/状态机）；

3组合：ReAct 作为「循环内核」，外包给确定性编排（LangGraph 等）——自由循环 + 外层护栏是生产标配（agent-系列 07 篇）。

07SECTION

五、本篇要点（复习卡片）


1谱系：CoT（分步想）→ Self-Ask（自追问）→ ToT（树状试错）→ ReAct（想+做+看循环）。

2ReAct 三拍子：Thought → Action → Observation → 循环——推理被观察「接地」。

3三个赢点：可解释 / 可纠错 / 工程极简——一切后续范式的最小公分母。

4三个局限：无全局规划 / 成本高 / 不可预测——引向 Plan-and-Execute。

5生产建议：ReAct 当内核、外层加编排与护栏（自由循环 + 确定性兜底）。

08SECTION

六、下一篇预告


第 02 篇：规划-执行与工作流范式——针对 ReAct 的「短视」，Plan-and-Execute 把「全盘规划」和「逐步执行」分离（Planner/Executor/Verifier/Refiner），DAG 与状态机把流程变成可控制的图。从「一个循环」到「一套工程」。
