03SECTION

一、反思自修正范式（Reflection）

1.1 谱系

范式

核心

关键设计

Reflexion

（2023）

失败后生成自然语言反思，存情景记忆，下次参考

反思 + 情景记忆 = 「verbal RL」（不调权重靠长记性）

Self-Refine

（2023）

生成 → 批评 → 修订，迭代到收敛

无外部反馈，纯自我批判循环

MIRROR

（2025）

行动前反思（预判不良）+ 行动后反思（纠错）

双记忆（短时+长时）+ 双时相反思

1.2 与 P&E 修订的区别

•P&E 的 Refiner：改计划/流程（结构化）；

•Reflexion：改行为记忆（心智）——把「这次的经验」沉淀下来，下次同类任务直接用；

•本质：反思 = 把执行结果变成学习信号（这是「自进化」的雏形，研究板块 05 篇展开）。

💡 学习要点：反思范式 =「把失败变成经验」不做梯度更新的「学习」——靠自然语言反思 + 记忆存储实现行为改进。成本极低、效果显著，是所有生产 Agent 都应该配的「小功能」。

2.2 关键设计原则（衔接 agent-系列 06 篇，这里讲范式视角）

1谁来拆：预定义流程（稳）vs 主控模型拆（灵活）——Manager-Worker 本质是「把拆和做分开」；

2传什么：传「结构化产物」（文档/代码/数据）而非闲聊——MetaGPT 的 SOP 做法；

3谁校验：每个子任务出口有验证（不合格退回）——没有校验的多 Agent = 接力传垃圾；

4上下文隔离：子 Agent 只带所需上下文——这是多 Agent 最重要的收益（避免单窗口超载）。

05SECTION

三、工程范式总览（板块一收尾）

code

基础循环：ReAct（01）

+ 规划执行：P&E / Workflow（02）

+ 纠错机制：反思（Reflexion/Self-Refine）＋结构化修订（Verifier/Refiner）

+ 扩展规模：多 Agent（Manager-Worker / 对等 / 组织）

= 生产 Agent 的完整范式武器库

•选型口诀：任务开放 → ReAct；任务复杂 → P&E；流程固定 → Workflow；容易出错 → 加反思；一个人干不完 → 上多 Agent。

06SECTION

四、本篇要点（复习卡片）

1反思谱系：Reflexion（记忆+反思=verbal RL）/ Self-Refine（自批评自修订）/ MIRROR（行动前预判+行动后纠错）。

2反思 vs P&E 修订：前者改「心智记忆」，后者改「流程计划」——可叠加使用。

3多 Agent 三形态：Manager-Worker（层级）/ 对等（讨论）/ 组织分工（SOP 模拟）。

4多 Agent 四原则：谁来拆 / 传产物 / 谁校验 / 上下文隔离。

5工程选型口诀：开放→ReAct；复杂→P&E；固定→Workflow；易错→反思；超载→多 Agent。

6板块一收官：基础循环 + 规划执行 + 纠错 + 扩展 = 工程范式武器库。
