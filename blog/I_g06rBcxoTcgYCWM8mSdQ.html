第 06 篇 · MCP 实战：给所有 Agent 写工具

02SECTION

导读

04/05 篇给「单个模型」写工具（function calling）。但现实中，同一套工具（查数据库、操作飞书、读文件）要在 Claude/ChatGPT/Gemini/自己的框架里重复接。MCP 解决「写一次、处处用」（原理见 agent-系列 05 篇）。本篇动手写一个 MCP Server，并讲 BFMCP 安全模式。

03SECTION

一、MCP Server 是什么

•架构：Agent/框架 = MCP 客户端；外部系统（数据库/API/文件）封装成 MCP 服务端；

•三原语：Tools：可执行动作（github.create_issue、db.query）；Resources：可读数据（Schema、文件、API 文档）；Prompts：可复用模板（代码审查模板等）；

•传输：stdio（本地开发）/ Streamable HTTP（远程生产）；2026-07-28 规范已无状态化。

04SECTION

二、最小实战：写一个「订单查询」MCP Server

python

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("orders") # 一个订单服务的 MCP Server

# ① Tools：可执行动作

@mcp.tool()

def query_order(order_id: str) -> str:

"""按 ID 查询订单状态（返回给 Agent 的文本结果）"""

# 真实实现：查数据库/业务系统

return f"订单 {order_id} 状态：已发货，预计 10-02 送达"

# ② Resources：可读数据（只读上下文，如 Schema）

@mcp.resource("orders://schema")

def orders_schema() -> str:

"""订单表结构（Agent 读取以理解字段）"""

return "订单表：id, product, status, eta"

# ③ Prompts：可复用模板

@mcp.prompt()

def order_inquiry(order_id: str) -> str:

"""引导 Agent 如何向用户说明订单状态"""

return f"用户查询订单 {order_id}，请说明状态与预计送达时间"

if __name__ == "__main__":

mcp.run() # 默认 stdio 传输，本地即可跑

•跑起来后：Claude Desktop / ChatGPT（Apps SDK）/ 任何 MCP 兼容客户端都能发现并调用这三个能力——不用为每个平台重写集成。

💡 学习要点：写一次 MCP Server = 全生态 Agent 可用集成一个 SaaS 工具的平均时间从 ~18 小时（各家手写胶水）降到 ~4 小时（MCP 标准化）。三原语的设计纪律：动作给 Tools、数据给 Resources、交互模板给 Prompts——一个 Server 三种能力配合最好。

05SECTION

三、BFMCP 安全模式（生产必读）

•问题：直接暴露「裸 SQL 查询」给 Agent = 攻击面过大（任意查、改敏感表、耗资源）；

•BFMCP（Backend for MCP，类比 BFF 模式）：MCP Server 只暴露业务级操作，真正的数据访问与权限控制放在后端服务：

•收益：Server 薄（好测好审）、权限在业务层（不裸奔）、可限流可审计（衔接 agent-系列 07 篇授权最小化）。

06SECTION

四、实战要点与踩坑

1工具粒度 = 自然意图：query_order 优于 execute_sql——粒度决定调用质量（agent-系列 04 篇）；

2参数 Schema 要描述清楚：jsonschema_description 帮助模型正确传参；

3返回要「给模型读」的文本：结构化 JSON/简洁 Markdown，别让模型二次解析复杂二进制；

4错误返回结构化：失败时给「原因 + 建议」，让 Agent 能修正重试。

07SECTION

五、本篇要点（复习卡片）

1MCP = 工具接入标准：客户端-服务端；三原语 Tools/Resources/Prompts。

2一次开发处处用：写一个 Server，Claude/ChatGPT/Gemini/自有框架都可用（集成 18h→4h）。

3BFMCP：Server 只暴露业务操作、后端管权限——防「裸 SQL」攻击面。

4粒度：工具 = 自然意图；描述清楚；返回模型友好文本；错误结构化。

5衔接：MCP 原理（agent-系列 05 篇）→ 实战（本篇）→ 安全（agent-系列 07 篇）。
