第 05 篇 · 自进化 Agent 范式：让 Agent 自己变强

02SECTION

导读

前面的范式都是「静态」的：部署即定型，执行完拉倒。自进化（Self-Evolving）范式回答一个新问题：Agent 能不能把执行结果变成学习信号，持续自我改进？ 2025-2026 年这个方向从理论进入实证（SWE-RL 自博弈 +10.4pp），是当前研究范式的最前沿。本篇用「what/when/how」三问拆解。

03WHY

一、为什么需要自进化

•传统模式：「一次执行」——任务完成就完，下次同类任务从零开始；

•现实世界的三个特征让这不够用：开放性：环境在变（API 升级、界面改版、数据漂移）；长程性：任务跨会话、需要跨会话积累；重复性：用户反复做相似任务——每次都重新发明轮子太浪费；

•核心思想：把执行结果变成学习信号，让系统修改自己的组件。

2.2 When to Evolve（何时进化）

•测试内（Intra-test-time）：单任务执行中，靠上下文学习/反思即时调整（最便宜）；

•测试间（Inter-test-time）：跨任务/会话，积累经验持久化（Reflexion 的延伸——从「本次长记性」到「永久长记性」）；

•越靠后越「贵」但越「持久」——演进时机的选择 = 成本与持久性的权衡。

05SECTION

三、三个标志性系统（2025-2026）

3.1 SWE-RL（Meta Superintelligence Labs，2025-12）

•自博弈：一个 Agent 同时扮演「注入 bug 者」和「修 bug 者」——先造 bug 再训练自己修；

•结果：SWE-bench Verified +10.4pp，不依赖任何外部数据——纯自博弈驱动的自我改进。

3.2 Voyager（2023，里程碑）

•Minecraft 中：Agent 把学到的技能写成可执行代码存入技能库，下次任务直接调用；

•效果：解锁物品 3.3×、科技树推进 15.3×——「会做事」被沉淀为「可复用技能」。

3.3 EvolveR（2026）

•离线自蒸馏：把交互轨迹提炼成可复用的抽象策略原则；

•在线交互：检索原则指导决策 + 策略强化迭代更新——从「重放解决方案」到「提炼可泛化的策略」。

💡 学习要点：自进化 =「从执行到学习」的闭环静态 Agent：执行 → 输出 → 完。自进化 Agent：执行 → 提取经验（反思/技能/策略） → 存储 → 下次调用。递归自我改进 2026 已从理论进入实证——这是 Agent 范式最重要的前沿信号。
