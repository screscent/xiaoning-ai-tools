二、最小实战：带搜索工具的 ReAct Agent

python

import anthropic, json

client = anthropic.Anthropic() # 需设 ANTHROPIC_API_KEY

# 1. 定义工具：让模型知道「有搜索能力可用」

tools = [{

"name": "web_search",

"description": "搜索网页并返回相关结果摘要",

"input_schema": {

"type": "object",

"properties": {"query": {"type": "string"}},

"required": ["query"],

},

}]

def web_search(query):

# 真实接入搜索 API（如 Tavily/Serper）；此处为示意

return f"关于「{query}」的模拟搜索结果……"

# 2. ReAct 循环：推理 → 工具调用 → 观察 → 再推理

def run_agent(user_query):

messages = [{"role": "user", "content": user_query}]

for step in range(5): # 最大步数护栏

resp = client.messages.create(

model="claude-sonnet-4-5", max_tokens=2048,

messages=messages, tools=tools,

)

# 检查模型是否请求调用工具

tool_call = next((b for b in resp.content if b.type == "tool_use"), None)

if tool_call is None:

return resp.content[-1].text # 无工具调用 → 输出最终答案

# 3. 执行工具，把结果回喂给模型（Observation）

result = web_search(tool_call.input["query"])

messages.append({"role": "assistant", "content": resp.content})

messages.append({"role": "user", "content": [

{"type": "tool_result", "tool_use_id": tool_call.id, "content": result},

])

return "达到最大步数，任务未完成。"

print(run_agent("帮我查一下 Agent 最新的开源框架"))

•五步解析（对照 agent-范式 01 篇）：工具定义：JSON Schema 告诉模型「有什么能力、参数是什么」；推理：模型决定「该查一下」并输出 tool_use；行动：你执行工具（这里是 web_search）；观察：把 tool_result 回喂；循环：模型看到结果再推理，直到不调工具直接回答。

💡 学习要点：裸骨架 = 一个 while 循环 + 工具回喂Agent 的本质不是魔法：「模型输出 tool_use → 你执行 → 结果回喂 → 模型再想」。框架（Eino/LangGraph）干的是把这个循环工程化（状态、重试、流式、追踪）。

05SECTION

三、实战避坑（官方/社区共识）

1Token 消耗爆炸：单 Agent 一次任务 token ≈ 普通聊天的 4 倍（每次循环都重发全部消息）——所以要有 max_steps 护栏和上下文管理；

2上下文污染：中间结果全塞进 messages，长任务会爆窗口——需要摘要/压缩（agent-系列 03 篇上下文工程）；

3工具描述即一切：description 写不好，模型就不会用或乱用——工具是「说明书」，不是「开关」；

4流式 tool_use 拼接：流式输出时 tool_use 参数可能分片，要攒齐再执行（与 Eino 踩坑同源）。

07SECTION

五、本篇要点（复习卡片）

1Agent 定义：能自己调工具的 AI；核心 = ReAct 循环。

2五步骨架：定义工具 → 模型出 tool_use → 执行 → 结果回喂 → 循环。

3工具描述 = 说明书：description 决定模型用不用、用得对不对。

4两大坑：token 4 倍成本（要护栏）、上下文污染（要压缩）。

5框架价值：把循环工程化——流式、状态、追踪、多 Agent。
