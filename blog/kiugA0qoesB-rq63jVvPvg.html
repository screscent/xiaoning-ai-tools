04SECTION

二、PTC：程序化工具调用（重点新机制）


2.1 它解决什么

传统 ReAct 循环的「乒乓球效应」：

code

LLM 推理 → 调工具 A → 结果塞上下文 → LLM 再推理 → 调工具 B → 结果再塞……又慢又贵

PTC 的做法：LLM 直接写一段完整 Python，在沙箱一次跑完：

python

# 模型生成（PTC 模式）：一次执行多次工具调用

orders = await toolA.query_orders()       # 查所有订单

chart = await toolB.generate_chart(orders) # 生成图表

return chart                              # 一次交付，无中间往返

•收益：少 N 次网络往返与上下文塞入 → 延迟与 token 大幅下降。

2.2 何时用 PTC / 何时用 ReAct（关键判断）

任务特征
用哪个
流程确定性强、结果无需 LLM 语义判断
PTC
（写代码一次跑完）
每步结果需要 LLM 理解再决策（如「分析合同风险等级再决定下一步」）
ReAct 循环
（LLM 决策点）

💡 学习要点：PTC =「能写死的流程交给代码，不能写死的交给循环」PTC 本质是「自动写代码」——适合确定性强、工具调用可编排的流程；一旦「下一步取决于语义判断」（LLM 决策点），就要退回 ReAct 循环。两者互补，不是替代。

05SECTION

三、Skills：知识胶囊


•物理形态：一个文件夹 = SKILL.md（核心说明）+ 脚本/代码 + 资源（文档/模板/示例）；

•作用：告诉模型「遇到这类任务该怎么做」——把专业操作流程、该用的模块、模板以模块化方式注入，不占满上下文；

•场景：PDF 处理技能、特定框架开发技能、公司内部规范技能；

•与 MCP 的区别：MCP = 「能做什么」（工具能力）；Skills = 「该怎么做」（知识与流程）。

06SECTION

四、Subagents：分而治之


•定位：把大任务拆给上下文隔离的子 Agent（对应 agent-系列 06 篇/范式 03 篇的 Manager-Worker）；

•与 PTC/Skills 的协同：子 Agent 可以带自己的 Skills（专业分工）、各自接自己的 MCP 工具（权限隔离）——四件套组合拳。

07SECTION

五、四件套协同全景（怎么配合用）


code

任务进来

→ Skills 告诉「怎么做」+ MCP 提供「能做什么」

→ 主 Agent（Subagents 组织）：拆任务 → 派给子 Agent

→ 子 Agent：确定流程用 PTC 连招、需要语义判断用 ReAct 循环

→ 关键节点 HITL 人工审批

•生产建议：先只上 MCP（接工具）跑通 → 加 Skills（灌知识）→ 复杂流程试 PTC（省成本）→ 任务大到拆 Subagents——四件套按需叠加，别一次全上。

08SECTION

六、本篇要点（复习卡片）


1四件套：MCP（接工具）/ PTC（连招执行）/ Skills（知识胶囊）/ Subagents（分工协作）。

2PTC 核心：LLM 写 Python 一次跑完多次工具调用——省往返省 token。

3关键判断：确定流程 → PTC；需要 LLM 语义决策 → ReAct 循环。

4Skills vs MCP：能做什么（工具）vs 怎么做（知识）——互补。

5协同路径：MCP → Skills → PTC → Subagents 按需叠加。

6板块二收官：单 Agent（04）→ 多 Agent（05）→ MCP（06）→ Claude 三维（07）——语言无关实战齐了。
