01SECTION

第 02 篇 · 规划-执行与工作流范式：从循环到工程

02SECTION

导读

ReAct（01 篇）的「短视」——走一步算一步——在长任务里会绕远路、烧 token、不可预测。Plan-and-Execute（P&E）给出相反设计：先全盘规划、再逐步执行。更进一步，DAG 与状态机把流程显式化，Agent 从「自由循环」变成「可控工程」。本篇是生产中 Agent 范式最常用的一课。

03SECTION

一、Plan-and-Execute 范式（P&E）

1.1 分离哲学

code

Planner（规划器）：先把大任务拆成步骤清单/计划

↓

Executor（执行器）：按计划逐步执行（每步调工具/模型）

↓

Verifier（校验器）：每步/整体验证结果对不对

↓

Refiner（精化器）：失败/偏差 → 修订计划 → 回到执行

•与 ReAct 的本质区别：ReAct 边想边做（交织），P&E 先想后做（分离）；

•好处：可预测：计划先给用户/系统看——能审、能改、能审批（HITL 天然友好）；省成本：规划一次，执行不重复思考（少很多 token）；抗错：Verifier/Refiner 让「执行错 → 修订计划」结构化，而非自由重试。

💡 学习要点：P&E =「谋定而后动」ReAct 像边走边问路，P&E 像先看地图再出发。计划先行的价值 = 可审（给人看）+ 可省（不重复思考）+ 可控（失败走结构化修订）——这是生产级 Agent 的默认姿势。

04SECTION

二、工作流范式（Workflow）：把流程变成图

2.1 为什么还要「工作流」

•单 Agent 自由循环不够，多步任务需要显式编排：谁先谁后、要不要并行、失败了怎么走；

•学术定义（Agent Workflow 综述 2508.01186）：Agent 工作流 = 角色 + 流程 + 规范语言 的结构化编排；

•两种表示：DAG（有向无环图）：步骤之间并行/串行，适合「可确定的流水线」；状态机（State Machine）：显式状态与转移，支持循环/重试/审批——LangGraph 的实现。

2.2 一个「状态机 Agent」长什么样（LangGraph 心智）

code

节点：规划 → 检索 → 生成 → 校验 → 完成

边： 规划→检索；检索→生成；生成→校验（不通过→回生成，重试≤3；超限→转人工）

•关键收益：控制面显式化——循环次数、重试上限、审批点、超时都是「图上的边」，可测试、可追踪；

•与自由 ReAct 的对比：自由循环「信任模型」，图编排「约束模型 + 兜底」——确定性兜底。

💡 学习要点：三范式 = 确定性滑杆ReAct（全灵活）→ P&E（半结构化）→ Workflow（全结构化）。生产里通常三层混用：框架层用状态机管流程、任务层用 P&E 规划、单步内用 ReAct 探索——按环节选确定性程度。

06SECTION

四、工程实践要点

1能确定就确定：机械步骤（查库/计算/转换）用流程代码，别让模型自由发挥；

2校验必须独立：Verifier 别用同一个「执行模型」自我评价——独立校验或规则校验（对齐「不靠自评」思想）；

3计划给人工审：高风险任务的计划先展示给人确认（HITL 审批点，agent-系列 07 篇）；

4状态可恢复：状态机 + 检查点——中途崩溃能续跑（LangGraph durable execution）。

07SECTION

五、本篇要点（复习卡片）

1P&E 四角色：Planner / Executor / Verifier / Refiner——先谋后动、失败走结构化修订。

2P&E 三价值：可审（给人看计划）/ 可省（不重复思考）/ 可控（结构化纠错）。

3工作流两表示：DAG（并行流水线）/ 状态机（循环/重试/审批，LangGraph）。

4三范式 = 确定性滑杆：ReAct（灵活）→ P&E（半结构）→ Workflow（全结构）；生产三层混用。

5实践：能确定就确定 / 校验独立 / 计划给人审 / 状态可恢复。

08SECTION

六、下一篇预告

第 03 篇：反思自修正与多 Agent 范式——执行会出错，除了 P&E 的结构化修订，还有「反思」这条心智路线（Reflexion/Self-Refine/MIRROR）；而单 Agent 搞不定时，多 Agent（Manager-Worker/对等/组织）是第三条路。三个范式合起来 = 工程侧的完整武器库。
