02SECTION

导读


第 04 篇说行动靠工具，但有个历史痛点：每家框架自己接工具（LangChain 一套、AutoGPT 一套、自研又一套）——给数据库写一次集成，每个框架都得重写。MCP（Model Context Protocol）像浏览器有 HTTP、IDE 有 LSP 一样，给「Agent ↔ 工具」一个统一协议：工具接一次，处处可用。本篇是 Agent 机制层的基石。

03SECTION

一、MCP 是什么


1.1 一句话

MCP 是「Agent 客户端」与「工具/数据服务端」之间的标准化连接协议（JSON-RPC 2.0）——把「模型怎么调用工具」统一成工业协议。

•2024-11 Anthropic 开源；

•2025-04 ChatGPT 接入（转折点：不再是 Anthropic 专属）；

•2025-12 捐赠 Linux Foundation 旗下 Agentic AI Foundation（AAIF，与 OpenAI/Google/Microsoft/AWS 共管）；

•2026-03：SDK 月下载 97M、公共服务器 9400+——业界默认工具协议。

05SECTION

三、2026-07-28 规范 RC 的四个升级（最新）


1无状态核心：协议层去会话——Mcp-Method 头路由、tools/list 可缓存，水平扩展如普通服务；

2Tasks 扩展：长时运行工作（异步长任务）成为一等公民；

3MCP Apps：服务端渲染 UI——工具不只返回数据，还能返回界面；

4授权对齐 OAuth/OpenID：企业级鉴权；另有正式弃用策略（协议可持续演进）。

•影响：远程 MCP 服务不再需要 sticky session/共享会话存储——部署成本与 HTTP 同级。

07SECTION

五、工程实践要点


1BFMCP 模式（Backend for MCP）：MCP 服务端只暴露业务级操作，后端承接数据访问与权限控制——避免把「裸 SQL 查询」直接交给 Agent（权限最小化，衔接 04 篇安全）；

2三原语并用：好的服务端不只 Tools，还用 Resources（给上下文）+ Prompts（标准化交互）；

3一个服务端多处用：写一次 MCP server，Claude/ChatGPT/Gemini/Cursor 全部可用——集成成本从 18 小时降到约 4 小时（2026 行业数据）。

08SECTION

六、本篇要点（复习卡片）


1MCP = Agent 的 HTTP：统一「Agent ↔ 工具」连接协议；2024-11 开源 → 2026 已成行业标准（AAIF 托管、97M 月下载）。

2三原语：Tools（动作）/ Resources（数据）/ Prompts（模板）——好服务端三者并用。

3两传输：stdio（本地）/ Streamable HTTP（远程）；2026-07-28 RC 核心无状态化。

4四个升级：无状态 / Tasks 长任务 / MCP Apps 服务端 UI / OAuth 授权对齐。

5分工：MCP 管「接工具」，A2A 管「接 Agent」——同一基金会治理。

6实践：BFMCP 防裸权限；写一次到处用。

09SECTION

七、下一篇预告


第 06 篇（板块二·机制）：多 Agent 协作与编排——一个 Agent 不够时怎么办：图编排（LangGraph，显式状态图）/ 角色制（CrewAI，团队分工）/ 交接制（OpenAI Agents SDK，子 Agent 委派）三范式对比，以及多 Agent 的通信与任务分发。MCP 给了工具，编排给了「组织」。
