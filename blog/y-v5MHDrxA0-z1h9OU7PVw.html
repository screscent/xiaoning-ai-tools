01SECTION

第 9 篇 · DeepSeek 使用方式：按原理选模式、配提示词、做 Agent

02SECTION

导读：用法不是玄学，是原理的下游推论

「怎么用 DeepSeek」和「DeepSeek 怎么造的」是同一件事的两面：

•知道推理是 RL 涌现的，你就明白为什么要给「思考模式」留预算；

•知道MoE 激活少、KV 缓存被压缩，你就明白为什么「上下文是便宜的输入」；

•知道思考已融入工具调用，你就明白 Agent 场景该怎么配；

•知道R1 对提示敏感、输出可读性曾有问题，你就明白提示词为什么要写清楚。

本篇把系列 8 篇的原理，逐条映射成 6 个使用决策。

一句话总结：用 DeepSeek = 回答三个问题——要不要思考？上下文放什么？要不要给它工具？

04SECTION

二、第一课｜思考模式：用「想多久」换「多准」

2.1 原理

•R1-Zero 证明：不教它怎么想，只奖励「想得对」，模型自己学会反思与验证（第 6 篇「Aha Moment」）；

•OpenAI o1 开了「测试时扩展」的头：思考得越长，难题答得越准——思考长度就是一张可调的计算预算；

•代价：思考模式 token 消耗显著更多、响应更慢。

2.2 操作：任务难度 ↔ 思考强度（V4 起三档）

思考强度 reasoning_effort

适用任务

例子

low

简单、有标准答案

翻译、格式整理、常识问答、简单代码补全

high

（默认日常）

一般推理 + 日常 Agent

业务代码、数据分析、工具调用流程

max

难题/边界探索

竞赛题、数学证明、复杂算法设计、长链 Agent 任务

两个铁律：

1简单任务别开思考：非思考模式又快又便宜，效果往往一样好；

2难题才开 max：max 的 token 消耗是 low 的数倍，只给真正值得的任务。

💡 学习要点：思考 = 计算预算，不是玄学开关官方甚至建议在 Agent 场景「复杂任务用思考模式 + max」。记住这个映射，你就知道为什么「同一个模型，换个档位就像换了个人」。

05SECTION

三、第二课｜上下文是「便宜的输入」

3.1 原理

•MoE 激活少：V4-Flash 每 token 只激活 13B——算力按激活量计费（第 3/5 篇）；

•KV 被压缩：MLA → DSA → CSA/HCA，百万上下文从「显存炸弹」变「标配」（第 3/7/8 篇）；

•成本结构：DeepSeek 一贯「输入便宜、输出贵、缓存命中更便宜」——把料一次性喂进去，比反复来回问省得多。

3.2 操作：把上下文当「外挂记忆」

1长文档一次塞入，不要分多轮：V4 支持 1M 上下文（官方服务标配）——合同、代码库、会议记录直接整份喂；

2关键信息放近处：HCA 对远处 token 做 128 倍高压缩、只保留「核心摘要」——最重要的指令/事实放在 prompt 前部或结尾，别埋在中间；

3开发者：开上下文缓存：同一批前缀重复使用时命中缓存，输入成本可再降一档（官方曾实现硬盘缓存降价 90%）；

4别为省 token 砍上下文：砍掉关键背景反而导致多轮补救，总成本更高。

💡 学习要点：Agent 场景尤其吃「读」有测算显示 Agent 代码任务的输入:输出可达约 154:1——这正是 V4.1 用 CED 结构「prefill 便宜、decode 精准」的原因（第 8 篇）。给 Agent 的料越全，它越不需要来回试错。

06SECTION

四、第三课｜会思考、还会用工具

4.1 原理

•V3.2 是首个把思考融入工具使用的模型：思考模式下也能多轮调用工具（第 7 篇）；

•V4 起 Agent 能力开源最强：Agentic Coding 开源第一，官方已适配 Claude Code / OpenClaw / OpenCode / CodeBuddy 等主流 Agent 产品，并支持 Function Calling、JSON Output、FIM 补全（第 8 篇）。

4.2 操作：Agent 场景怎么配

mermaid

flowchart LR

U["用户任务"] --> M1["思考：拆解步骤"]

M1 --> T1["调用工具（读文件 / 跑代码 / 搜网页）"]

T1 --> O1["观察工具返回"]

O1 --> M2["再思考：分析结果"]

M2 --> T2["再次调用工具（按需多轮）"]

T2 --> O2["观察结果"]

O2 --> M3["收敛：给出最终答案"]

•开发者接入：工具调用：用 Function Calling（OpenAI 兼容接口）给模型注册工具；结构化输出：用 JSON Output 约束返回格式，避免自己解析自由文本；代码补全：用 FIM（中间补全）在编辑器/IDE 光标处补全，配合插件体验最佳；Agent 框架：直接接入官方适配过的 Claude Code / OpenClaw / OpenCode 等脚手架，不用从零造轮子。

•用户侧：在 App/网页里勾选「深度思考 + 工具」，就能让模型读文件、算数、查资料后给出更准确的回答。

💡 学习要点：给模型「环境」比给模型「答案」更重要V3.2 用 1800+ 环境、8.5 万指令合成数据训出泛化工具能力，且官方明示「未针对评测集特训」——所以把真实的工具与环境交给它，它才会发挥出训练时的泛化能力。

07WHY

五、提示词技巧：原理告诉你「为什么要写清楚」

5.1 原理依据（来自官方论文与发布说明）

1R1 对提示敏感（论文明确写出）：同样的问题，措辞不同结果差异大——提示词要「给足约束」；

2格式奖励：推理模型被训练成把思考包在 <think>…</think> 里（第 6 篇）——别要求它把思考过程当答案输出；

3语言一致性奖励：R1 曾出现中英混杂（第 6 篇）——提示词别中英混写；

4官方建议：V2.5 发布说明提示「场景效果变差时，重新调整 System Prompt 与 Temperature」。

09SECTION

七、成本与部署：原理决定「怎么省」

7.1 计费结构（官方多轮调整，以现行价为准）

•输出 token 比输入贵数倍 → 让模型「少说废话」：明确要求简洁、控制 max_tokens；

•缓存命中输入几乎免费档 → 公共前缀复用（system prompt、长文档头部）；

•思考模式按 token 计费 → effort 档位就是省钱档位。

7.2 本地部署：Distill 家族

•用 R1 蒸馏的 1.5B / 7B / 8B / 14B / 32B / 70B 稠密模型（基于 Qwen/Llama）可本地跑，14B 超越当时最强开源推理 QwQ-32B-Preview，32B/70B 对标 o1-mini（第 6 篇）；

•原理启示：蒸馏 = 「大模型的推理模式灌给小模型」——本地小模型也能有像样的推理，适合隐私/离线场景；

•MIT License，明确允许蒸馏——你甚至可以拿 DeepSeek 的输出蒸馏自己的专用小模型（官方协议支持）。

10SECTION

八、常见误区（原理纠偏）

误区

真相（原理依据）

「思考模式 = 更强，全程开」

思考是计算预算，简单任务非思考又快又好（第一节）

「上下文越长越好，拼命塞」

远处信息被 HCA 高压缩，关键信息要放近处（第三节）

「让推理模型做多轮闲聊/角色扮演」

R1 论文自述：函数调用/多轮/角色扮演/JSON 弱于通用模型（第五/六节）

「提示词越短越好」

对提示敏感 + 格式奖励 → 给足约束与格式反而更稳（第五节）

「中英混着问没关系」

语言一致性奖励：混写容易触发混输出（第五节）

「API 贵是因为模型大」

输出贵、缓存便宜、effort 可控——成本结构由 MoE 激活决定（第七节）

11SECTION

九、本篇要点（复习卡片）

1两个开关：思考（reasoner/chat）× 规模（Pro/Flash）——先判难度，再拧旋钮。

2思考 = 计算预算：reasoning_effort low/high/max 对应简单/日常/难题。

3上下文是便宜的输入：1M 标配、一次喂全、关键信息放近处、开缓存。

4思考已融入工具：Function Calling / JSON / FIM / 主流 Agent 框架直接接。

5提示词要「给约束」：边界、格式、示例、temperature、单一语言。

6成本三招：控输出长度、复用缓存、按难度调 effort。

7本地 = Distill 家族：1.5B~70B 免费可商用，MIT 允许蒸馏。
