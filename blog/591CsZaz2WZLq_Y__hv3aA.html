01SECTION

用"心理模型"驱动 LLM：这套范式成不成立，边界在哪


方向成立，但有严格边界。它是一套叠加在基座模型之上、外部的架构范式——不是让大模型拥有心理，也不是模型自带的能力。

这句话得先说清楚，因为它最容易被读成两种极端：一种是把它当万能解药，装上就变强；另一种是把它当玄学，一概否定。两种都错，而且错在同一处——没把"外部架构"和"模型原生能力"分开。

02SECTION

一、先分开两个同名的概念


中文里"心理模型"和"心智模型"经常被当成一回事，这一步不切干净，后面所有结论都会跟着错。

第一类是心理动力学模型（Psychodynamic）：动机、驱力、情绪冲突、人格特质、防御机制——一整套关于"内在状态"的模型。

第二类是心智模型（Mental Model）：主体对外部世界、任务、因果的内部表征。主流 Agent 论文里大量研究的是这一类，回答的是"它怎么理解世界"。

这篇文章讲的是第一类：把心理动力学 / 人格-情感系统放在外层，作为约束与引导框架，管住基座模型的生成过程。两者的差别不在措辞，而在管的是"内在状态"，还是"世界表征"。

03WHY

二、为什么这条路成立：三类工程收益


现在主流的 Agent 范式，绝大多数是任务驱动、工具驱动、目标-规划驱动。它们的短板高度一致：长会话里人格漂移、行为前后矛盾；只回答"任务完成了没有"，不回答"我以什么姿态完成"；跨任务时行为模式碎片化，做 A 一套性格、做 B 另一套。

心理模型驱动的做法是：在基座之上叠一层独立的内在状态层——驱力、情绪状态、人格特质、约束规则；这一层每一轮输出一组约束条件注入生成流程，模型在这个边界之内自由生成。工程上换来三样东西。

收益一：行为收敛，抑制漂移。 生成不再完全交给模型自由发挥，每一轮都有显式约束在场：当下动机是什么、情绪基调如何、哪些表达禁止、思考的优先顺序是什么。外部资料给出的经验值，是"显式心理状态层可以降低长会话输出方差、一致性改善约三成"。这里必须标注一句：这是外部资料转述，我没有独立复核，也没有受控 A/B 实测，只能当方向性参考，不能当承诺。

收益二：跨任务的行为统一。 纯 SOP-Skills 体系有个天然的结构问题：任务 A 一套流程、任务 B 一套流程，流程之间没有共同的"主体"，于是同一个 Agent 在不同业务里的性格与思维方式会割裂。心理层放在顶层做总控，所有 skills 与流程都受它约束，行为底色就能统一。

收益三：动机显式化、可观测。 普通 Agent 的目标来自用户输入——用户不说目标，它就没有内在倾向。这一层可以提供第二层动机源：偏好、价值取向、思考优先级。需要强调的是，这是工程模拟的结构化动力学，不是人类潜意识——它的每一项都是可枚举、可存储、可回滚的参数，不玄。

外部资料里提到过若干原型（如 MENTIS、Psychodynamic-Multi-Agent、LEKIA2.0）来支持这条路线的可行性。同样标注信息性质：这些是外部资料转述，我没有逐一核实原文，列在这里只作为进一步检索的线索。

04SECTION

三、四个必须知道的天花板


这条路真正的风险不在"能不能做"，而在"以为它顺便解决了别的问题"。下面四条，每条配一句工程处置。

第一，基座本身没有心理学机制。

模型权重里不存在驱力、情绪、本我自我超我；心理动力学完全是外层搭的一套状态机，属于上层脚手架，权重不会因此发生任何变化。由此推出一条硬要求：如果架构不做解耦，把整套心理理论一次性塞进系统提示词，那就退化成"加长版人设 prompt"——上下文一紧张，约束被稀释、被覆盖，照样漂移。正确做法是独立状态存储 + 每轮动态注入精简约束片段，而不是一次性灌入长文本。

第二，经典理论很多是不可证伪的。

精神分析里相当一部分概念（潜意识、防御机制）在科学界长期存在争议，难以量化、难以严格实验验证。工程上必须做形式化改造：理论只作思想来源，实现必须是可参数化、有明确输入输出的组件。举个具体例子——"防御机制"这个词，直接把文本描述丢给模型是错的做法；正确做法是把它写成条件-动作规则：出现 A 情境，则启用 B 约束，限制输出范围。

第三，过约束会压低推理能力。

如果心理层的规则写得过于厚重，会出现一个反直觉的现象：大量算力被用来满足人格约束，逻辑推演的空间被挤压，模型"变笨"——推理简化、回避复杂推导、优先满足人格要求，任务质量反而下降。处置办法是分层：人格层管方向、边界、风格、动机；基座管逻辑、计算、推导。 两层职责分离，人格层不去干涉具体演算。把这件事做到极致的形态，是"心智模型 + 执行模型"的双模型分工——如实说明一句：这在我们这里目前是设计原则与方向，不是已经落地的运行形态。

第四，它不解决幻觉，也不能替代 SOP 与工具。

它管的是风格、立场、动机、边界；不修复底层幻觉与逻辑漏洞，也不会提升基座本身的数学、代码与工具调用正确率。正确定位是：心理层是顶层的控制器与约束器，与规划、工具、知识库叠加协同，不是二选一。 反过来，"只要心理模型做好，SOP 和工具就不重要"，是明确的错误定位。

06SECTION

五、落地准则（五条）


一、定位在顶层，而不是在全部。 完整体系是：心理-人格动力学层（顶层约束）+ 流程与 skills（业务执行）+ 工具与 API（外部操作）+ 知识库（记忆）+ 基座模型（推理），多层协同。

二、严格区分"理论来源"与"工程组件"。 以心理动力学为思想来源，内部实现必须是结构化、状态化的模块；拒绝把心理学书本文本当提示词用。

三、优先解耦。 心理模块独立，不要整段揉进静态系统提示词。静态部分只作兜底，真正的驱动来自独立状态模块每轮输出的约束集合。

四、配一个冲突消解器。 驱力、情绪、人格、防御规则维度一多，多事件叠加必然出现互相矛盾的约束——一条要求直率、一条要求委婉，同时激活，行为就会摇摆。必须有优先级仲裁，而这一层会实打实推高系统复杂度。

五、变更必须过人工闸门。 如果接入递归自我改进闭环，让 Agent 自主修改人格与心理约束，微小的规则改动会层层传导、显著改变整体行为，进而产生对齐漂移。重大心理参数变更必须人工审核确认，不允许全自动修改。

08SECTION

七、结论


这套范式成立，但它成立的方式是"当顶层约束用"，而不是"当银弹用"。三句话收在这里：

一、它解决的是主体连续性、行为收敛、跨任务统一；不要指望它解决幻觉与底层推理错误。

二、工程成败的关键只有四个点：独立状态模块、分层解耦、冲突仲裁、人工闸门。 只做成一大段静态提示词，这套范式绝大部分优势都会消失，只剩下负担。

三、它适合持续交互型 Agent；对一次性的简单任务，投入产出比很低。

09SECTION

八、落到我们自己的路线：顶层心理模型，底层 Agent OS


前面讲的都是这套范式的通用边界。回到我们自己的做法，它可以压成一句话：顶层是心理模型，底层是 Agent OS。

这两层各管一头，边界先划清。

心理模型在最上面，管的是"以什么状态、什么立场、什么边界去做"——动机、情绪基调、人格特质，以及哪些表达禁止。它不碰具体怎么算、怎么调用工具。

Agent OS 在下面，管的是"这件事具体怎么做"——编排流程、调用工具、读写记忆、跑校验与门禁，把一轮请求从头走到尾。大模型是被 OS 调用的推理引擎，是零件，不是架构的边界。

这么分的直接好处是：心理层变厚，不会把推理挤掉；OS 层的工程能力增长，也不会反过来污染人格。两层各自可迭代，中间只靠两个接口对接——向下是"约束集合"，向上是"执行结果"。

再往细一层，Agent OS 这一侧主要有四件事：把请求编排成可执行的流程；按需调用工具与外部 API；维护分层记忆（什么该常驻、什么该按需读、什么只留当前会话）；以及在结果出闸之前做校验与留痕。心理模型这一侧则只做一件事——每轮输出一组约束，交给执行侧去遵守。

前面第五节的五条落地准则，我们就是按这个结构落位的：心理状态独立存储、每轮动态注入而不是一次性灌进静态提示词；理论上只作思想来源、实现一律落成结构化组件；两层职责分离，人格层不干涉具体演算；冲突有裁决顺序，不临场拍；涉人格与底线的重大变更，人工确认后才生效。

这样一套结构下来，如果只留一句总结：心理模型决定"像不像同一个人"，Agent OS 决定"这件事能不能做成"——两件事分开做，才都不打折。
