第 01 篇 · Claude 1 与宪法 AI：对齐路线的原点


02SECTION

导读


2021 年，OpenAI 副总裁 Dario Amodei 带团队出走成立 Anthropic，公开宣言是：「我们担心 AI 走太快而忘了安全。」 2023-03 推出的 Claude 1 承载了这个立场——它不是参数最大的模型，但它是第一个把「安全原则」写进训练流程（而非事后过滤）的大模型。

03SECTION

一、宪法 AI（Constitutional AI）三步


code

第 1 步 原则清单（宪法）

   人类写「有帮助 / 无害 / 诚实 / 不歧视…」的原则条文

第 2 步 自我批评（RLAIF）

   模型输出 → 按宪法自我批评 → 修订成合规回答 → 用修订数据监督微调（SFT）

第 3 步 自我打分（RL）

   用「是否违反宪法」做奖励信号，强化学习训练（AI 反馈替代人类反馈）

1.1 与 RLHF 的根本区别

1.2 为什么重要

•对齐从「黑盒偏好」变「可写代码」：原则条文可以像法律一样修改、版本化、公开讨论；

•可扩展性：模型越强，越难靠人逐条打分——「让 AI 审 AI」是必然方向（后来各家的 RLAIF/红队 AI 都是这个思想的延伸）。

💡 学习要点：宪法 AI =「给 AI 一部法律，而不是一个打分表」打分表会过时、会偏、且无法覆盖未知场景；法律条文可审查、可演进。Claude 的全部后续（无害性、诚实性、系统卡）都建立在这个「规则显式化」的地基上。

04SECTION

二、Claude 1（2023-03）的产品事实


•定位：安全 + 有帮助并重的对话助手（当时 GPT-3.5 的竞品）；

•亮点：倾向拒绝危险请求（宁可拒绝不错放——「harmless」优先）；

•弱项：能力不及同期的 GPT-4（安全与能力的初始权衡，Anthropic 选择前者）；

•定价先例：按 token 计费进入 API 市场。

2.1 早期「性格」

•被评测者称为「谨慎到啰嗦」：对政治/医疗/法律问题过度回避——对齐过度的早期样本（对齐税 §llm-理论 03）；

•教训：后来各版逐步放宽「有帮助性」，走向「该拒绝的拒绝、该答的答」。

05SECTION

三、Claude 2（2023-07）：长上下文与编码


•上下文 100K token（当时行业天花板，可读整本书）；

•编码能力显著提升（Codex 之外的选项）；

•论文同步公开 Constitution AI 细节——把方法论开放给行业。

06SECTION

四、本篇要点（复习卡片）


1宪法 AI 三步：原则条文 → AI 自我批评修订（SFT）→ AI 自我打分 RL（RLAIF）。

2vs RLHF：标准从「人工偏好」变「公开条文」；反馈从「人打分」变「AI 审 AI」。

3Claude 1（2023）：安全优先、宁拒勿放；对齐过度 → 早期「谨慎啰嗦」。

4Claude 2（2023）：100K 长上下文 + 编码增强 + 方法论开源。

5原点意义：对齐 = 可写条文、可审查、可演进——Anthropic 的 DNA。

第 02 篇：Claude 3 家族与 3.5——2024 年 Anthropic 推出 Opus/Sonnet/Haiku 三档：最强/均衡/最快。其中 Claude 3.5 Sonnet 成为年度口碑之王（编码、写作、性价比全面领先，被开发者称为「被低估的 SOTA」）。这一篇讲「三档产品化」如何让安全路线第一次赢得大众市场。
