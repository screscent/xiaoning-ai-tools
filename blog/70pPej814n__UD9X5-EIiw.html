01SECTION

第 09 篇 · 形态实战：编码 / 研究 / 常驻 Agent

02SECTION

导读

框架（01-03）、通用（04-07）、工程化（08）都是「技术」。本篇是「产品」：把技术装进三个被市场验证的形态——编码 Agent（最强落地，SWE-bench 74.9%）、研究 Agent（deep research，几分钟顶几小时）、常驻 Agent（7×24 后台干活）。每类给「形态定位 + 搭建骨架 + 实战要点」。

03SECTION

一、编码 Agent（Coding Agent）

•形态：读代码库 → 定位问题 → 改代码 → 跑测试 → 提 PR——「编程同事」；

•代表：Claude Code、Codex、Qwen3-Coder、Cursor；

•搭建骨架（语言无关）：代码库索引（RAG）→ ReAct/Agentic 循环（读→改→测）→ 沙箱执行 → HITL（写文件/跑命令确认）；

•实战要点：长程保持：一个 issue 十几步——用 checkpoint/上下文压缩（agent-系列 03 篇）；沙箱隔离：代码执行必须隔离环境（跑炸不伤主库）；评测：SWE-bench 思路——用「真实 issue 修没修好」衡量（不是「像不像代码」）。

💡 学习要点：编码 Agent =「结构化环境里最好做的 Agent」代码有语法、有测试——环境可验证性高，所以 Agent 落地最强。你的第一个生产 Agent 建议从编码/文档处理这种「可验证」场景切入。

04SECTION

二、研究 Agent（Deep Research）

•形态：开放问题 → 自动规划 → 多轮搜索 → 来源筛选 → 带引用报告——「调研助理」；

•代表：ChatGPT Deep Research、Gemini Deep Research、Claude deep research；

•搭建骨架：推理模型（o1/R1 系做深度规划）→ 搜索工具（MCP/API）→ 引用记录 → 综合成文；

•实战要点：引用强制：报告必须带可点击来源——对抗幻觉第一防线（agent-系列 10 篇）；来源可信度：官方 > 二手 > 社区，模型打分；迭代校验：矛盾信息交叉验证（反思机制，agent-范式 03 篇）；成本控制：深度研究 token 消耗大——设搜索轮数上限。

05SECTION

三、常驻 Agent（Resident / Background Agent）

•形态：长期在线——监听事件、周期巡检、按时触发，「一直在干活的员工」；

•代表：个人智能体雏形（Dots/Muse 的后台形态）、监控/报告/自动化 Agent；

•搭建骨架：触发（事件/定时/轮询）→ 循环（感知→决策→行动→校验）→ 状态持久化 → 健康检查 → 通知主人；

•实战要点（常驻是最难工程，agent-系列 10 篇详述）：幂等：同一事件触发两次不能重复副作用（发两次邮件）；去重：事件去重键 + 时间窗；停滞检测：多轮无进展要自我报告；预算：单轮 token/时间上限——常驻 = 无限轮 × 每轮都要便宜。

💡 学习要点：三形态 = 三条不同的「护城河」编码靠「环境可验证」、研究靠「引用纪律」、常驻靠「工程可靠」。选形态 = 选你团队最难的坑——都值得做，但别一次全做。

06SECTION

四、本篇要点（复习卡片）

1编码 Agent：读库→改码→跑测→提 PR；沙箱 + 长程保持 + SWE-bench 式评测——结构化环境最强落地。

2研究 Agent：规划→搜索→引用→报告；引用纪律 = 防幻觉第一防线。

3常驻 Agent：事件/定时/轮询触发 + 状态持久化 + 健康检查——最难的工程（幂等/去重/停滞检测）。

4选型：从「可验证场景」切入第一个生产 Agent。

5衔接：形态 = 技术（01-08）的产品化，趋势（10 篇）是形态的下一代。
